# JSON CPU profiles

Each directory contains Samply Firefox profiles, precise per-PC symbols (including DWARF inline frames), and exclusive sample summaries. `before` is the implementation delivered at `6de705b`, before the regression fixes; `after` is the runtime committed at `d23014d`, including explicit cache pairs and exact-chunk/64-byte ASCII scanning. The profile binaries use `--no-default-features --features simd`, matching the benchmark harness. Intermediate `a41c8eb` and `236544a` profiles are retained in the `experiments` archives. Environment files retain both binary hashes. These are CPU sample percentages, not percentages of wall time or inclusive call-tree totals.

Both workloads run 2,000 metered calls against the 1,048,536-byte fixture from `scripts/json_fixtures.py`. `parse` is `JSON.parse`; `shape` is `JSON.parse_as` into the packet shape. The SIMD release builds retain debug information. Profiles cover the whole harness process, including argument import, call setup, returned-value release, and a negligible amount of startup and final encoding. The timer in `compare.py` has a narrower scope, so profiles are explanatory rather than replacement timings.

On darwin, capture with `~/.cargo/bin/samply record --save-only --unstable-presymbolicate --rate 1000 --output PROFILE.json.gz BINARY INPUT.json 2000 timing`. On shannon, Samply's recorder refuses `perf_event_paranoid=2`; the equivalent unprivileged capture uses `perf record -F 1000 -e cpu-clock:u --call-graph dwarf,16384`, followed by `samply import --save-only --unstable-presymbolicate`. No security settings were changed. Both hosts were checked for gates; shannon's busy desktop file indexer was paused for the final captures and measurements, then resumed. The earlier x86 capture had the indexer present; use the paired benchmark runs, rather than differences in profile duration, for speed comparisons. A private extracted perf binary and its libraries in `/tmp/json-perf-tool` provide the recorder. Using one software event avoids mixing the separate hybrid CPU PMU events.

For exact inline attribution, load a copy of the profile **without** its `.syms.json` sidecar in `samply load --no-open`, from the build worktree while its matching binary and object files are present. `symbolicate.py PROFILE.json.gz SERVER.log` queries `/symbolicate/v5` for every distinct sampled address. The presymbolicated sidecar alone collapses some addresses to function-entry locations and loses the inline accounting frames. The saved `.pcs.json.gz` files make analysis independent of those temporary build paths.

Run `python3 analyze.py DIRECTORY ...` to regenerate summaries. Each sample walks its expanded stack from the leaf outward and uses the first matching category. Allocator images/functions and allocation-capacity helpers are allocation; step checks, reservations and memory-ledger reference counts are accounting; byte/UTF-8 classifiers are scanning/validation; string buffers, key-cache lookup and unescaping are string decoding; integer/float conversion is number decoding; hashes, value wrappers and their reference counts/destructors are value construction/release. Type proofs and normalization have their own category. Parser dispatch, frame handling and delimiter/whitespace control appear separately, as does other runtime work. This is an explicit attribution convention; inlined instruction ownership and unsymbolicated system code limit precision.

macOS's private malloc symbols are unavailable, so those samples are attributed by the `libsystem_malloc.dylib` image and retained as image offsets. Linux also has some unnamed libc routines; those are attributed to the first identifiable caller. The raw profiles and PCs retain the evidence rather than inventing private function names.

`controls` contains the M4 portable `array_sum` investigation: two million metered calls, nominal 2 kHz sampling, original baseline versus `a41c8eb`. Generated `Value::Kind` drop code rose from 11.3% to 14.3% of samples despite identical instructions. Its common path crossed a code page boundary in the latter binary; the constant key-cache initializer removes generated construction code and moves that path off the crossing. Saved disassembly documents the addresses. The VM and value source are unchanged.
